# 입찰가 암호화 키 관리

분양사와 유니피커가 입찰가 암호화에 쓸 RSA 키 쌍을 만들고, **자기 회사 GitHub 비공개 저장소**에 보관하는 웹 페이지입니다.

- 주소: <https://bombommobile.github.io/bid-keyweb/>
- 파일: `index.html` 하나. 외부 스크립트와 라이브러리를 쓰지 않습니다.

## 이 페이지가 하는 일

1. **GitHub 연결**: 귀사 비공개 저장소와 접근 토큰을 넣고 저장소를 확인합니다.
2. **키 만들기**: 브라우저 안에서 RSA 키 쌍을 만듭니다. 키에 이름을 붙입니다.
3. **PC에 저장**: 키명세서, 공개키, 개인키 파일 3개를 PC에 저장합니다.
4. **GitHub에 저장**: 두 파일을 귀사 저장소에 커밋합니다. 커밋 시각이 키를 만든 시점의 기록이 됩니다.

유니피커 입찰시스템 관리자 페이지에는 **키명세서를 먼저**, 이어서 **공개키**를 올립니다. 입찰시스템은 공개키의 해시가 키명세서와 같은지 확인합니다. 개인키는 입찰이 마감된 뒤에만 같은 관리자 페이지에 제출합니다.

**키명세서**(`{키 이름}_{해시 앞 8자리}_keyspec.json`)에는 키 이름, 저장 폴더, 만든 시각, 공개키 해시, 파일 이름이 들어 있습니다. 공개 정보만 담고, 개인키와 관련된 값은 넣지 않습니다.

## 키와 토큰은 어디로 가는가

| 대상 | 가는 곳 | 가지 않는 곳 |
|---|---|---|
| 개인키 | 귀사 PC, 귀사 GitHub 비공개 저장소 | 유니피커 서버를 포함한 다른 모든 서버 |
| 공개키 | 위와 같음. 그리고 사용자가 직접 입찰시스템에 올림 | — |
| GitHub 토큰 | `api.github.com` 호출에만 씀 | 다른 모든 서버 |

- 페이지는 `Content-Security-Policy: connect-src https://api.github.com` 로 GitHub API 외의 통신을 브라우저 차원에서 막습니다.
- 토큰은 기본적으로 페이지 메모리에만 있고, 페이지를 닫으면 사라집니다.
- 사용자가 **「브라우저에 저장」** 을 고르고 경고에 동의한 경우에만 저장소 이름과 토큰을 그 브라우저의 `localStorage` 에 저장합니다. 이 기능은 보안을 위해 권하지 않습니다. 같은 브라우저를 쓰는 사람과 같은 주소(`bombommobile.github.io`)의 다른 페이지가 저장된 값을 읽을 수 있습니다.

## 왜 공개 저장소인가

분양사는 「이 페이지가 개인키나 토큰을 몰래 다른 곳으로 보내지 않는다」를 직접 확인할 수 있어야 합니다.

- 유니피커 서버가 이 페이지를 내려주면, 유니피커가 언제든 코드를 바꿀 수 있어 이 의심을 풀 수 없습니다.
- 그래서 코드를 공개 저장소에 두고 GitHub Pages 로 서비스합니다. 코드가 바뀌면 공개 커밋 기록이 남습니다.
- `main` 브랜치는 저장소 소유자만 바꿀 수 있습니다. 강제 푸시와 삭제는 막혀 있습니다.

## 검증하는 방법

분양사 IT 담당자는 아래 순서로 지금 서비스되는 페이지가 공개된 코드와 같은지 확인할 수 있습니다.

1. 서비스 중인 페이지의 해시를 구합니다.

   ```bash
   curl -s https://bombommobile.github.io/bid-keyweb/ | shasum -a 256
   ```

2. 이 저장소 `main` 의 `index.html` 해시와 비교합니다.

   ```bash
   curl -s https://raw.githubusercontent.com/bombommobile/bid-keyweb/main/index.html | shasum -a 256
   ```

3. 두 값이 같으면 서비스 중인 페이지가 공개 코드와 같습니다. 코드를 읽을 때는 `<script>` 안에서 `fetch(` 를 찾으면 됩니다. 모든 호출이 `https://api.github.com` 으로 향합니다.

GitHub Pages 는 배포 직후 몇 분 동안 이전 버전을 보여줄 수 있습니다. 값이 다르면 잠시 뒤 다시 확인하세요.

## 귀사 저장소에 저장되는 파일

```
keys/{날짜}_{해시 앞 8자리}/public.pem    공개키 (SPKI PEM)
keys/{날짜}_{해시 앞 8자리}/private.pem   개인키 (PKCS#8 PEM)
keys/{날짜}_{해시 앞 8자리}/keyspec.json  키명세서 (키 이름, 만든 시각, 공개키 해시, 파일 이름)
keys/history.jsonl                        만들기·PC 저장·내려받기 기록
```

- 키 이름: 필수, 1~30자, 한글 가능, 저장소 안에서 중복 불가
- 브랜치: `main` 고정

## 암호 방식

| 항목 | 값 |
|---|---|
| 알고리즘 | RSA-OAEP 2048비트, SHA-256 |
| 공개키 형식 | SPKI PEM |
| 개인키 형식 | PKCS#8 PEM |
| 공개키 해시 | SHA-256(SPKI DER), 16진수 64자. 입찰시스템 관리자 페이지에 표시되는 값과 같은 방법으로 계산합니다 |

## 필요한 것

- 귀사 GitHub **비공개** 저장소 (Add README 를 켜고 만들어 `main` 브랜치가 있어야 합니다)
- Fine-grained 접근 토큰: 그 저장소 하나만, **Contents: Read and write**
- 최신 Chrome, Edge, Safari

자세한 준비 방법은 페이지 안 「GitHub 준비하기」에 있습니다.
